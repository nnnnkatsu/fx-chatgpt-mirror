# Worker 更新说明（尚未部署）

`worker.js` 是完整替换文件，保留原有指标函数、四个货币路径、六个周期、analysis 结构和 60 秒缓存时间。不要把任何密钥写进文件。Sakura API、launcher、PATH nonce 和 GitHub 被动镜像不需要改动。

## 不能只粘贴后直接发布

这一版使用一个共享 Durable Object，跨请求和货币持久化额度账本。必须同时注册 `FxCoordinator`（SQLite）并绑定变量 `FX_COORDINATOR`。普通内存变量不能保证全局每分钟限额。缺少绑定时行情接口会返回 503，不会绕过额度控制。

建议使用本目录的 wrangler.toml 首次部署：它注册类、绑定和三个 UTC 定时规则。不要覆盖已有其他绑定/路由；本配置是需要合并的模板。保留已有 Secret `TWELVE_DATA_API_KEY`。若只使用网页代码编辑器，请先完成上述类注册和绑定再发布，不要单独上线代码。Cloudflare 当前配置说明：https://developers.cloudflare.com/durable-objects/get-started/

## 首次额度初始化（先配置，再首次请求）

`FX_BOOTSTRAP_USED_CREDITS`：填写该 Key 在过去 24 小时已经消耗的 credits 保守上界，0–800。它只在账本首次创建时读取；之后修改变量不会清空账本。若无法确认，保持默认 800：首个请求之后会保护性暂停新的上游调用 24 小时。只有确实过去 24 小时没有调用，才填 0。不能为了立即启用直接填 0。

`FX_SCHEDULE_ENABLED`：先保持 `false`，配置绑定、额度初值和原有 Secret 后验证一次正常 Sakura analysis。确认结果和 GitHub 更新后改为字符串 `true`，启用定时预取。首次部署前保留原 Worker 版本以便回滚；不要删除额度存储或改共享实例名字来重置限额。

如果同一个 Twelve Data Key 还在此 Worker 以外被调用，这些外部调用不会自动进入账本，应统一入口或另行扣减预算。本方案以 price/time_series 每个请求 1 credit 计费；上线前以账户实际响应/额度面板核对。

GBPUSD 保留临时查询，不新增定时采集。周末无定时采集。07:57 仅用于 08:00 检查前准备。

每天预取 24 次，每次 analysis 7 个上游请求，按每请求 1 credit 估算 168 credits。检查时若 Sakura 主入口成功但 60 秒缓存已过期，可能再次消耗最多约 168；正常预取加检查约 336/day，临时查询另计，不承诺总共只用 168。

共享额度：滚动 24 小时最多 800；定时调用在累计将超过 600 时拒绝，为手动使用留余量；75 秒窗口最多 8，保守覆盖网络延迟。额度不足返回 429，不盲目重试。失败请求也计入预算。相同接口 60 秒内并发请求复用结果，不改写源时间。

UTC Cron：`2 * * * *`、`57 2,6,10,22 * * *`、`37 3,7,11,23 * * *`。代码内部再次按 JST 过滤工作日与时间。定时延误超过 90 秒跳过，不集中补发；同一事件只尝试一次。

## 更新链

Worker 定时取得 analysis → 调用既有 Sakura `/fx/<pair>/analysis` → Sakura 读取同一份 60 秒内 Worker 缓存并落盘 → 原每 2 分钟被动镜像上传 GitHub。

镜像不请求 Twelve Data。Worker 不持有 GitHub Token。不新增服务器高频行情 cron。Worker 日志显示 `sakura_cache_updated` 才表示 Sakura 返回了同一 fetched_at_utc；GitHub 成功需另外看镜像状态。

手动需要行情时仍打开 Sakura launcher，再使用它给出的 analysis 链接；同样受共享限额约束，60 秒内可能复用缓存。没有新增公开无限强制刷新入口。
